## 📖 소개

Streamlit 기반의 텍사스 홀덤 학습·연습 도구입니다. 두 가지 모드를 하나의 앱에서 제공합니다.

1. **📊 실시간 승률 & 수학적 어드바이저** — 내 핸드/보드를 입력하면 몬테카를로 승률과 팟 오즈(콜 필요 승률)를 즉시 계산해 +EV 의사결정을 돕습니다.
2. **🎮 1:N 토너먼트 / 멀티플레이** — AI 상대 솔로 플레이, 또는 6자리 코드로 친구와 함께하는 실시간 온라인 토너먼트를 즐길 수 있습니다.

> 📱 모바일(가로모드 포함) / 💻 PC 레이아웃과 ☀️ 라이트 / 🌙 다크 테마를 지원합니다.

## ✨ 핵심 기능

| 영역 | 기능 |
| :--- | :--- |
| **승률 어드바이저** | 169개 시작 핸드 조합표, 실제 무늬 선택, 프리플랍·플랍·턴·리버 몬테카를로 승률 추정 |
| **팟 오즈** | 베팅 비율 기반 콜 필요 승률 / 오즈 비율 / 아웃츠 환산, +EV·-EV 판정 |
| **멀티플레이 룸** | 6자리 코드로 방 생성·참가, 방장 규칙(시작칩·리바이·BB) 공유, 빈 좌석 자동 AI 충원 |
| **서버 권위 엔진** | 모든 게임 상태를 서버가 단일 소스로 관리, 전역 락으로 동시성 직렬화 |
| **게임 규칙** | 블라인드/앤티, 사이드 팟 분배, 올인, 리바이, 턴 제한시간(기본 60초) 자동 처리 |
| **실시간성** | 자동 새로고침으로 상대 액션 반영(내 차례·버튼 조작 시에는 입력 보존) |
| **UX** | 무작위 좌석 배정, 무작위 초기 딜러, 실시간 내 패 족보 표시, 모바일 컴팩트 레이아웃 |

## 🚀 빠른 시작

Python 3.10 이상을 권장합니다.

```bash
# 1) 의존성 설치
pip install -r requirements.txt

# 2) 실행
streamlit run app.py
```

브라우저에서 `http://localhost:8501` 로 접속합니다. 같은 서버에 접속한 사용자끼리 방 코드를 공유하면 함께 플레이할 수 있습니다.

## ☁️ 배포 (Streamlit Community Cloud)

1. `app.py`, `poker_engine.py`, `requirements.txt`, `README.md` 를 GitHub 저장소 최상위에 올립니다.
2. [Streamlit Community Cloud](https://streamlit.io/cloud) 에 로그인하고 저장소와 `app.py` 를 선택해 배포합니다.
3. 생성된 `*.streamlit.app` 주소로 접속합니다.

> ⚠️ **멀티플레이 주의:** 현재 멀티플레이 상태는 **단일 서버 프로세스의 메모리**에 저장됩니다. 서버가 재시작되면 방이 사라지며, 여러 인스턴스로 확장(스케일 아웃)하면 상태가 공유되지 않습니다. 소규모 친목용에는 충분하지만, 실제 서비스화는 아래 로드맵을 참고하세요.

## 📁 프로젝트 구조

```
holdem-advisor/
├── app.py              # Streamlit UI (탭·테마·모바일 레이아웃·멀티플레이 렌더러)
├── poker_engine.py     # 서버 권위 홀덤 엔진 (방/좌석/핸드/베팅/쇼다운/사이드팟)
├── requirements.txt    # 의존성 (streamlit, treys, plotly, streamlit-autorefresh)
└── README.md
```

### 아키텍처 한눈에 보기

- **상태 소유권:** `app.py` 의 `@st.cache_resource` 로 프로세스 전역 `rooms` 딕셔너리와 `threading.Lock` 을 만들어 모든 세션이 공유합니다.
- **동시성:** 상태를 바꾸는 모든 엔진 호출(`join_room`/`start_hand`/`player_action` 등)은 락을 잡은 채 실행하고, 렌더링은 상태를 깊은 복제(snapshot)한 뒤 수행해 경합을 피합니다.
- **핸드 평가:** `treys` 라이브러리로 5장 최적 조합을 평가하고, 승률은 몬테카를로 시뮬레이션으로 추정합니다.

## 🧭 실제 서비스로 만들려면? (로드맵)

지금 구조는 "한 서버 프로세스 = 한 게임 서버"인 프로토타입입니다. 실서비스로 가려면 단계적으로 다음을 보강합니다.

| 단계 | 할 일 | 이유 |
| :--- | :--- | :--- |
| **1. 상태 외부화** | 인메모리 `rooms` 를 **Redis** 등 외부 저장소로 이전 | 서버 재시작·다중 인스턴스에서도 방이 유지/공유됨 |
| **2. 실시간 전송** | 자동 새로고침(polling)을 **WebSocket**(FastAPI/Socket.IO 등) 기반 푸시로 교체 | 지연·부하 감소, 즉각적인 액션 반영 |
| **3. 인증/계정** | 세션 토큰 대신 **로그인·사용자 계정**(OAuth 등) 도입 | 재접속·좌석 소유권·전적 관리 |
| **4. 영속 저장** | 전적·칩·방 이력을 **DB**(PostgreSQL 등)에 저장 | 데이터 보존, 통계·랭킹 |
| **5. 공정성/보안** | 서버 측 셔플 검증, 레이트리밋, 치팅 방지, 입력 검증 강화 | 신뢰 가능한 게임 |
| **6. 확장/운영** | 컨테이너화(Docker) + 오토스케일, 로깅/모니터링, 룸 샤딩 | 트래픽 증가 대응 |
| **7. 아키텍처 전환** | UI(프런트)와 게임 서버를 분리, Streamlit은 데모/관리 콘솔로 | 실시간 게임엔 전용 백엔드가 적합 |

> 💡 **핵심:** Streamlit은 데이터 앱/프로토타입에 최적이며 실시간 멀티플레이 게임 서버로는 한계가 있습니다. 실서비스라면 **게임 로직은 전용 백엔드(WebSocket + Redis/DB)** 로 옮기고, 지금의 `poker_engine.py`(이미 UI와 분리된 순수 모듈)를 그 백엔드의 코어로 재사용하는 것이 가장 현실적인 경로입니다.

> 📐 1단계(Redis 상태 외부화)의 구현 가능한 수준 상세 설계는 **[docs/SERVICE_DESIGN.md](docs/SERVICE_DESIGN.md)** 를 참고하세요.
